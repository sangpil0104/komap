# 12개 base B4 입력 재사용: 구현 최적화 프로토콜

앞선 base12 후속 탐색과 별도 단계다. 결과를 보고 계수/fold 후보를 추가하지 않는다. 코드 검사에서 같은 B4 전처리 파라미터의 fold들이 영상마다 resize·zcdf·padding·CPU→GPU 입력 전송을 반복하는 것을 확인했다. **가중치 12개, 모델 순서, 입력 dtype·값, softmax·복원·확률 누적 순서, TENT5·결합·후처리를 그대로 유지**하고 같은 영상 내 동일 전처리 설정의 입력 tensor만 재사용한다. 이미지 사이에는 cache를 공유하지 않는다.

- 고정키: scale, norm, input mode, feat stats. 서로 다르면 공유하지 않는다. 네트워크 출력/확률을 공유하거나 fold 평균을 생략하지 않는다.
- 앞선 GPU7 실험 완료 또는 실패와 worker 종료를 확인하고 새 단일 GPU7 실행을 시작한다. 기존 audit·앞선 실험·새 실험 flock을 모두 확보한다. 타 작업은 건드리지 않는다.
- 실제 326 2-fold 및 329 4-fold에서 같은 원본 이미지로 기존/입력 재사용 출력의 tensor 값과 preprocessing 호출 수를 비교한다. 정확한 tensor 동일성이 깨지면 중단하고 별도 결함으로 기록한다.
- 이후 원본 valid20부터 한 번 재추론, PNG/GT 재채점. 같은 base 및 lite15 대비 평균 손실 ≤0.01%p, 최악 이미지 손실 ≤0.10%p gate를 적용한다. 수치 흔들림·클래스별·이미지별 변화를 기록한다.
- 품질 통과 시 새 control12와 cache12를 A-B, B-A, A-B 순으로 각3회 전부 원본 valid20부터 재실행한다. 모델 로드/component/fusion 포함 시간을 기록한다. 중앙값 10% 이상 감소·반복 품질 gate 전부 통과·GPU7 타 프로세스 간섭 없음일 때만 이번 조건의 탐색 시간 개선으로 표시한다. 현재 공유 CPU exhaustive 작업과 부하를 보존하며 해당 부하 조건을 명시한다. 결과가 다른 환경의 속도를 보증하지 않는다.
- test10 원본 추론 후 기존 base 마스크 일치율만 확인한다. 정확도나 test mIoU는 없다. 성능 조건을 보고 전처리 설정이나 캐시 정책을 재선택하지 않는다.
- 체크포인트 수/크기는 그대로다. 모델 정확도 상승이나 저장 용량 감소로 포장하지 않고 추론 구현의 실제 시간 개선 여부를 별도로 보고한다. 기존 base 코드는 수정하지 않는다.
