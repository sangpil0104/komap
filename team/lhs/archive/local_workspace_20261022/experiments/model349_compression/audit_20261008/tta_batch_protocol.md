# 고해상도 D4 view batching 사전 고정 검증

기존 14/12/10/TENT3 실험을 끝낸 뒤, 원래 lite15의 모든 15개 모델과 EMA 밝기 경로를 보존하는 별도 FP16 저장판을 만든다. 계수, 해상도, 원본·밝기 보정 입력, TENT 5-step, HRNet, 269와 B4 전 fold를 바꾸지 않는다. OpenCV 2 threads를 쓰고, 고해상도 768 D4의 8개 view를 순서 그대로 유지하면서 4개씩 concatenation해 두 번의 model forward로 처리한다. 각 view의 inverse와 합산 순서는 원래와 동일하게 유지한다. 기존 단일 view의 수치와 부동소수점 차이가 있을 수 있어, 동등 성능을 사전에 주장하지 않는다.

용량은 원래 lite15 FP32를 별도 경로에 FP16로 저장해 줄인다. 연산 자체를 FP16 저장으로 줄이는 것이 아니다. 고해상도 추론은 기존부터 AMP를 사용하며 새 최적화는 view batch=4다. 추론 때 BN은 eval이므로 새 영상에서 TENT 이전/이후 상태를 서로 공유하지 않는다. 각 영상의 적응 모델은 여전히 새로 로드한다.

최종 판정은 원래 lite15 전체 파이프라인(default OpenCV)와 새 15-FP16/OpenCV2/D4batch4 파이프라인을 같은 GPU7에서 A-B-A-B-A-B로 원본 valid20 각각 3회 실행한다. 첫 B의 평균 손실 >0.01%p 또는 이미지별 최대 손실 >0.10%p이면 이후 B 반복은 기각하고 추가 진행하지 않는다. 통과 시 전체 3회 각각의 점수·최악 손실을 확인하고, 중앙값 시간 10% 이상 감소와 checkpoint bytes 감소가 있어야 탐색 채택 기준을 통과한다. 초기 실행에 따라 view batch를 다시 조정하지 않는다.

이 방법은 valid 점수를 높이려고 fold/계수를 고르는 대신 계산 배치를 바꾸는 재현 최적화다. 다만 이 valid를 반복 사용했으므로 독립 데이터 일반화를 새로 입증한 것은 아니다. test10에는 정답을 사용하거나 점수를 주장하지 않고, 과거 lite15 마스크와의 일치만 확인한다. 새 번들의 GPU 사용 시작 전 상태 확인/flock을 유지하고 다른 사용자 GPU 작업을 건드리지 않는다.
