## 평가식과 구성

valid 정답은 20장입니다. 이미지마다 Al3Ni·Primary Si·Al·Eutectic Si의 IoU 4개를 평균하고 다시 20장 평균한 image mIoU를 사용합니다. 해당 이미지에 없는 클래스와 empty union은 IoU=0입니다. 픽셀 전체를 합산한 global IoU나 클래스별 NaN 제외 평균으로 바꾸지 마세요.

12개판은 EMA를 제거한 lite14 기반으로, 326 B4의 fold 1·3만 유지하고 329 B4는 네 fold 모두 유지합니다. HRNet336·native269·나머지 고해상도 경로·TENT5를 유지합니다. 정확한 구성은 설정과 체크포인트 목록으로 재확인해 주세요. FP16은 저장 형식이고 FP32 module에 로드하므로 FP16 연산·VRAM 절감과 구분해야 합니다.

## 확인된 수치와 한계

| 구성 | 공식 valid image mIoU | 체크포인트 bytes | 전체 추론 시간 |
|---|---:|---:|---:|
| 원본349 | 80.0683465% | 2,598,535,369 | 1895.94초, 과거 단회 |
| lite15 | 80.0643596% | 1,641,328,608 | 366.56초, 과거 단회 |
| 이번 lite15 | 80.0644243% | 1,641,328,608 | 614.73초, 부하 영향 큰 단회 |
| 이번 OpenCV2 lite15 | 80.0644560% | 1,641,328,608 | 384.27초, 단회 |
| 이번 14개 FP16/TENT5 | 80.0656365% | 765,130,532 | 409.98초, 단회 |
| 이번 12개 FP16/TENT5 | 80.1255610% | 683,320,900 | 364.28초, 단회 |

12개판은 이번 lite15 대비 평균 +0.0611367%p, 14개 FP16 대비 +0.0599245%p입니다. 14개 FP16 대비 11장 개선·9장 악화이며, 가장 나쁜 A191_step4_sample3는 -0.0922867%p입니다. 이번 lite15 대비 최악은 -0.0930182%p로 한도 0.10%p에 가깝습니다. 원본349 대비 평균은 +0.0572146%p지만 최악 이미지 손실은 -0.2683304%p입니다. 기존 lite15 자체도 원본349 대비 A125에서 -0.2282%p 차이가 있어, lite15 기준과 원본349 기준을 혼동하면 안 됩니다.

남길 fold는 여러 차례 본 동일 valid에서 탐색했습니다. 원본 영상부터 재추론하고 label PNG/GT로 별도 채점한 것은 수치 재현이며, 새 표본의 독립 일반화 검증은 아닙니다. 정확한 탐색 후보 수·선택 이력은 추가 감사가 필요합니다. 12개판은 단회만 추론했고 12개판의 test10 재추론도 하지 않았습니다.

별도 15개 D4 후보와 HRNet 연산 후보는 각각 A-B 3회 측정했습니다. 시간 중앙값은 395.71→395.72초와 408.67→395.82초(3.14% 감소)로, 품질은 통과했지만 사전 반복 시간 10% 감소 기준에는 미달했습니다. 이 반복 결과를 12개판 결과로 돌려쓰지 마세요. 이 두 후보의 test10 마스크 일치율 99.99491%/99.99408%도 12개판의 결과가 아닙니다. test10에는 GT가 없어 test mIoU를 주장할 수 없습니다.

기존 품질 기준은 lite15 대비 평균 하락 ≤0.01%p, 최악 이미지 하락 ≤0.10%p입니다. bytes 감소와 실제 시간 감소도 필요하며, 단회 시간으로 개선을 확정하지 않습니다. 이후 연산 후보의 반복 채택 기준은 각 3회 중앙값 10% 이상 감소였습니다. 12개판은 현재 탐색 후보로 보관하며 기본 릴리스를 교체하지 않았습니다.

## 검토 요청

1. 파일의 평가식·입력 SHA·클래스 순서·체크포인트 구성·수치가 설명과 일치하는지 확인하세요. 가능하면 기존 마스크의 CPU 재채점으로 오류를 확인하되 GPU 실행은 하지 마세요. 파일 접근이 없으면 직접 검증했다고 쓰지 마세요.
2. 12개판의 평균 상승에 대해 후보 선택 편향, 다중 비교, 20장 표본의 불확실성, specimen별 상관, EMA 제거·FP16·fold 축소의 혼재를 검토하세요. “과적합 가능성”과 “과적합이 입증됨”을 구분하세요.
3. 어떤 이미지·클래스가 상승을 만들었는지, 악화가 특정 specimen·밝기·조직에 몰리는지 확인하세요. 메타데이터가 없으면 이름만으로 group이나 분포를 확정하지 마세요.
4. 같은 valid의 paired/group bootstrap이 설명할 수 있는 것과 후보 선택 편향을 교정하지 못하는 부분을 명시하세요. 사후 valid split이나 train70 평가를 독립 검증처럼 포장하지 마세요. OOF 검증을 제안하면 해당 이미지와 specimen이 모델 훈련에 포함되지 않도록 확인할 절차를 제시하세요.
5. 다음 판정을 분리하세요: 현재 valid 수치 재현 / 일반화 개선 / 저장 용량 개선 / 실제 속도 개선 / 기본판 채택 가능성. 현재 가능한 주장과 금지해야 할 주장을 각각 적어주세요.
6. 새 정답 데이터 확보가 가능한 경우와 불가능한 경우의 최소 후속 검증 계획을 제안하세요. 후보·설정·후처리를 동결하는 시점, specimen 분리, 비교 기준, 사전 평균·최악 이미지 한도, 동일 GPU 교차 반복 시간 측정을 포함하세요. 사용된 valid를 재사용하는 방법의 한계를 명시하세요.
7. 실용적인 결론으로 12개판을 기본판 채택 / 탐색 후보 유지 / 기각 중 어디에 두는지 근거를 제시하세요. 현재 판단을 반박할 수 있는 증거도 적어주세요.

답변 형식: 먼저 5줄 이내 결론, 다음으로 확인된 사실과 문제점(심각도·근거 파일), 마지막으로 우선순위가 있는 최소 검증 계획을 작성하세요. 성능 상승을 자동으로 일반화 개선으로 해석하거나, 반대로 추가 데이터가 없다는 이유만으로 실제 개선 가능성을 부정하지 마세요.

위 프롬프트는 test10 재추론 전의 검토 요청이다. 이후 사용자 요청으로 12개·10개판의 실제 test10 추론과 specimen 조건부 안정성 분석을 완료했다. 현재 검토에서는 [새 결과 보고서](../generalization_20261008/report.md) 및 해당 JSON을 우선 확인하고, 위 “12개판 test10 미실행”은 과거 상태로 해석해야 한다. 독립 일반화 개선은 여전히 미확인이다. 기존 train-valid specimen 중복 7개와 현재 학습 출력/동결 배포판 텐서 불일치도 발견했으므로 기존 OOF를 이 후보의 성적으로 인용하면 안 된다.
