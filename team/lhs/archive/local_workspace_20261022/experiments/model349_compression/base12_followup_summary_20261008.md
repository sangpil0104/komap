# 12개 FP16 base 후속 탐색 종합 결과

## 결론

이번 범위에서 품질과 시간 조건을 충족한 새 후보는 없었다. 사용자 지정 12개 FP16 base를 유지한다. 기존 원본·릴리스·base 포인터를 변경하지 않았고 새로운 가중치 학습도 하지 않았다.

base: valid20 image mIoU **80.1255610%**, 체크포인트 **12개 / 683,320,900바이트**. FP16은 저장 형식이며 로드 후 FP32를 사용하므로 저장 형식 자체의 계산량/VRAM 개선을 주장하지 않는다.

조건은 base12와 기존 lite15 각각 평균 손실 ≤0.01%p, 최악 이미지 손실 ≤0.10%p다. 첫 단계 프로토콜 본문은 이중 조건 표현이 불완전했지만 실행 전 코드에는 명시되어 있었다. TENT4는 base 조건에 실패한 것이 아니다. 기존 lite15 대비 A74 손실 −0.1177126%p로 이중 조건을 충족하지 못했고 반복 시간/test 대상으로 올리지 않았다. 후속 두 프로토콜에서는 이중 조건을 분명히 명시했다.

11개판은 **626,688,625바이트**, base보다 8.29% 작지만 품질을 유지하지 못했다. 해당 후보의 단회 842.54초 및 TENT4의 835.31초는 당시 큰 CPU 부하에서 나온 진단값이므로 속도 판정에 쓰지 않았다.

Al3Ni gamma329 0.6/0.7의 **저장 확률 탐색**은 각각 80.1397563/80.1562526%였다. 최악 이미지 A153 손실 −0.1647439/−0.3167205%p로 기각했고 두 후보는 원본 재추론하지 않았다. 공식 확정 성능으로 취급하지 않는다. Al3Ni 계수 변경 후 전체 4클래스 재정규화가 일어나 다른 클래스도 영향을 받는다. 첫 단계 report 말미의 일반적인 ‘계수 후보 원본 재추론’ 표현은 실제 수행 범위와 맞지 않으며, 실제 원본 후보는 11개/TENT4 두 개였다.

## 입력 재사용의 반복 시간과 동일성

326의 2-fold·329의 4-fold가 반복하던 동일 전처리 입력을 같은 이미지 안에서만 재사용했다. 가중치, forward, 확률 누적 순서를 유지했고 probe tensor뿐 아니라 valid20 전체 326/329/336/269 저장 확률도 기존 base와 정확히 같았다. 최종 마스크의 미세 변동은 변경하지 않은 TENT 경로에서 나타났으며 정확도 향상으로 주장하지 않는다.

동일 조건 교차 순서 A-B / B-A / A-B로 각3회 측정했다.

| 회차 | 기준판 초 | 재사용판 초 | 시간 감소율 |
|---|---:|---:|---:|
| 1 | 419.65 | 431.39 | −2.799% |
| 2 | 356.85 | 422.62 | −18.430% |
| 3 | 345.37 | 343.29 | +0.603% |
| 중앙값 | 356.85 | 422.62 | −18.430% |

전체 시간에는 모델 로드, 모든 경로 추론과 fusion을 포함한다. 공유 서버의 기존 CPU 작업 부하가 내려가며 양쪽 시간도 크게 변했다. 이 결과로 입력 재사용이 근본적으로 18% 느리다고 단정할 수는 없으나, 이번 조건에서 사전 10% 시간 감소를 입증하지 못했다. 한 장 old-first probe의 빠른 후보 값에는 초기화/순서 효과가 섞여 있으므로 개선 근거로 쓰지 않는다. 모든 반복은 이중 품질 조건을 통과했다.

## test10

품질을 통과한 입력 재사용판을 원본 test10부터 재추론했다. 기존 12개 base와 **9,074,964픽셀 중 12픽셀 차이, 99.9998678% 일치**했다. 추론 208.36초는 단회 진단값이다. 정답이 없으므로 test mIoU/정확도는 없다. 다른 후보는 사전 품질 조건을 넘어서 후속 test를 진행하지 않았다.
