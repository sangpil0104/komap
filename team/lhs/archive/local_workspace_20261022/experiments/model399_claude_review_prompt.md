## Candidate methods and decision

Compare these as competing single interventions; the Step4-conditioned option is a distinct alternative to this global class-weight draft:

1. Literal teammate-style static inverse pooled source prior `w ∝ 1/p`, with its literal `z−log(w)` correction. Note that this assumes training crop prior `q` is sufficiently close to `p`.
2. Sampler-aware static weighting `w ∝ 1/q`, with a predeclared correction mapping crop prior `q` to target/source prior `p`; apply the same target-prior calibration to the unweighted paired control. State clearly why pooled-pixel `p` or mean-per-image `p` is the defensible target-prior approximation.
3. Dynamic semantic-segmentation Recall Loss, which scales class CE according to per-class false-negative rate/recall rather than fixed inverse-frequency weights. The primary paper studies Synthia and Cityscapes with DeepLab/ResNet and reports competitive mean IoU, but not KoMaP. Its pinned [metric implementation](https://github.com/PotatoTian/recall-semseg/blob/a3f7fc3d12468ac41e78740122d8820c087c7aa6/ptsemseg/metrics.py#L18-L36) accumulates one confusion matrix across images and uses `nanmean` over class IoUs; this is pooled/global mIoU with empty classes omitted, not the competition's image-wise four-class mean with empty-union=0. The [paper](https://arxiv.org/abs/2106.14917) warns that static minority weighting can increase false positives. The pinned [RecallCrossEntropy source](https://github.com/PotatoTian/recall-semseg/blob/a3f7fc3d12468ac41e78740122d8820c087c7aa6/ptsemseg/loss/recall_loss.py#L10-L39) and [trainer's class-weight branch](https://github.com/PotatoTian/recall-semseg/blob/a3f7fc3d12468ac41e78740122d8820c087c7aa6/train.py#L828-L865) were inspected. RecallCrossEntropy computes hard `argmax` false-negative rates separately on each mini-batch and applies those weights to pixelwise CE; for Model392 this would be batch-local over four patches, not a stable epoch/global recall estimate. The released implementation also assumes CUDA tensors and has brittle ignore-index remapping when a batch has fewer than two distinct false-negative classes; a faithful KoMaP adaptation would need a device-safe, empty/single-class-safe implementation. Importantly, the reference trainer's static `WeightedCE`/`BalancedCE` branch counts classes by iterating its validation loader. The pinned [Synthia config](https://github.com/PotatoTian/recall-semseg/blob/a3f7fc3d12468ac41e78740122d8820c087c7aa6/configs/deeplab_synthia.yml#L5-L20) specifies separate `train` and `val` splits, so do not port that static-weight calculation; any class priors here must use only each outer-training fold. This caveat applies to those static-weight branches, not automatically to the paper's main RecallCE run, whose config selects `RecallCE`. Assess batch-local dynamics, implementation changes, thin-Eutectic risks, and interaction with Dice/boundary loss before recommending it.
