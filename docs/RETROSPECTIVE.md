# 대회 기록과 회고

예선 탈락 후 남은 실험 근거를 모은 문서입니다. 주최 측의 공식 test 점수, 순위, 컷 점수와 상세 평가 사유는 확인하지 못했습니다. 특정 설계나 제출 용량이 실제 탈락 사유였다고 단정하지 않습니다.

## 기록으로 확인되는 내용

- 최종 제출은 lite13(R7+E5+F1), 팀 제출 가중치의 valid20 image mIoU는 80.779378%입니다.
- 서버 재학습 결과는 80.471931%입니다. 제출 가중치와 재학습 가중치는 다르므로 두 결과를 구분합니다.
- lite20의 100회 시드 탐색에서는 80.255846%에서 80.479068%로 개선됐습니다. 여기서 100회는 구성 모델의 학습 작업 수이며, 완전한 앙상블 100개를 학습했다는 뜻이 아닙니다.
- train70 B4로 fold 모델을 교체한 실험은 79.797640%였으며, 기존 8개 HR 시드와 결합한 최고 결과도 79.899812%였습니다. 교체가 항상 개선을 만들지는 않았습니다.
- valid 20장으로 체크포인트·결합 비율·모델 조합을 반복 선택했습니다. 개선폭을 독립적인 일반화 성능의 향상으로 해석하기 어렵습니다.
- 일부 초기 실험은 빈 클래스 IoU=1을 사용했습니다. 이후 빈 클래스 IoU=0으로 통일된 기록과 비교하려면 같은 정의로 다시 채점해야 합니다.
- 전체 모델은 여러 학습 단계, OOF 예측, 상별 결합과 보정기를 포함합니다. 점수뿐 아니라 추론시간·가중치 수·재현 절차까지 함께 관리할 필요가 있었습니다.

## 다음 실험에서 바꿀 점

1. 제출 형식·실행 환경·파일 크기 제한을 시작 전에 확인하고, 작은 제출물을 먼저 끝까지 실행합니다.
2. 시편 단위 OOF를 개발·선택의 주된 근거로 사용하고, 별도의 최종 검증 데이터를 남깁니다.
3. 빈 클래스 처리와 데이터 분할을 실험 시작 전에 고정하고 평가 코드를 공통으로 사용합니다.
4. 작은 점수 차이는 시드 편차·이미지별 변화·계산 비용과 함께 판단합니다.
5. 오류가 남는 상과 경계 위치를 분석하고, 복잡한 조합 추가 전에 단순한 모델의 오류 원인을 확인합니다.
6. 공식 심사 결과를 확보하면 현재의 추정을 그 근거로 다시 검토합니다.

팀에서 작성한 [예선 탈락 분석 원문](../team/lhs/docs/예선_탈락_분석_20261022.md)도 보존했습니다. 원문의 원인 순위와 test 점수 추정은 팀의 가설이며 공식 결과가 아닙니다.
