# Model349: 100개 구성 모델 시드 탐색

기본 GPU는 **물리 4,5,6,7**, 환경은 Conda **komap**입니다. 사용자가 명령을 실행해야 학습이 시작됩니다.

```bash
cd /Data3/sppark/komap/experiments/model349_seed100_gpu4567_v1
./start_nohup.sh
```

실행기는 `nohup`을 사용하고 PID·로그 경로·`tail -f` 명령을 출력합니다. 터미널 실행은 `./run.sh train --execute`입니다.

학습 없이 확인:

```bash
./run.sh plan
./run.sh check
./run.sh train  # --execute 없이는 사전 점검만 수행
```

## 100개 학습 작업

| 구성 모델 | 학습 수 | 시드 | 시작 가중치 |
|---|---:|---|---|
| Model269 | 16 | 3407–3422 | 기존 Model257 |
| Model347 | 8 | 3423–3430 | 기존 Model336 |
| Model336 | 12 | 3431–3442 | 동일 ImageNet encoder |
| Model347 | 8 | 3443–3450 | 새 Model336 상위 2개에서 각각 4개 |
| Model329 | 8 | 3451–3458 | 4-fold 2세트, 각 fold에 연속 시드 |
| Model326 | 8 | 3459–3466 | 4-fold 2세트, 각 fold에 연속 시드 |
| Model123 EMA | 40 | 3467–3506 | 기존 Model109 |

합계 **100개**입니다. GPU는 작업이 끝나면 다음 작업을 가져가며, 한 GPU에서 이 실행기의 학습 두 개를 동시에 실행하지 않습니다. CPU의 GPU 인덱스 순서와 무관하게 UUID로 각 worker에 GPU 한 개만 노출합니다. 빠른 Model269·347·123을 먼저, 이후 Model336·후속347·B4를 처리합니다.

Model123은 실제 Model349 구성 가중치 중 마지막 학습 단계가 가장 짧습니다(기존 약 2분 15초). Model62 등 더 짧은 선행 단계는 최종 구성 가중치가 아닙니다. 현재 규칙에서 EMA는 검증 20장 중 `A186_step2_sample2`, `A44_step4_sample3` 두 장에 사용됩니다. 해당 두 장만 다시 추론하고 나머지 18장의 기존 기본 확률을 재사용합니다. 이 후보의 개선은 두 이미지에 한정되므로 별도의 일반화 근거로 해석하지 않습니다.

B4는 4개 fold가 모두 완료된 세트만 최종 모델로 평가합니다. 따라서 100개 학습을 모두 완료하면 최종 Model349 형태로 비교하는 후보는 **88개**이고, 최종 조합 하나를 선정합니다. 기본 평가에는 원래 가중치를 포함합니다.

## 시간과 재개

기존 RTX 4090 실측 기준 학습만 GPU 4개에서 약 6시간 50분이며, 별도 추론·조합 평가·저장 시간이 추가됩니다. 10시간은 목표 예산이며 절대 종료 시각을 보장하지 않습니다.

기본 `--hours 10 --reserve-hours 1.25 --budget-mode pause`: 8시간 45분 안에 끝날 것으로 예상되는 작업만 새로 시작하고, 1시간 15분을 최종 평가·저장에 남깁니다. 실행 중인 작업은 완료까지 기다립니다. 속도가 예상보다 느리면 학습 100개를 모두 끝내지 못할 수 있으며 `budget_paused` 상태와 완료 개수를 기록합니다. 완료 후보만 최종 평가하고, 미완료 작업을 조용히 삭제하거나 성공으로 표시하지 않습니다.

미완료 작업 재개(추가 세션의 예산은 다시 10시간):

```bash
./start_nohup.sh --resume /Data3/sppark/komap/experiments/model349_seed100_gpu4567_v1/outputs/runs/seed100_실행ID
```

시간보다 **100개 완료를 우선**하려면 처음부터 다음을 실행합니다. 10시간을 넘길 수 있습니다.

```bash
./start_nohup.sh --budget-mode finish-all
```

중단·실패 시 이미 완료한 작업은 유지하고, 미완료 작업만 새 `attempt_N` 폴더에서 처음부터 다시 실행합니다. 학습 도중 optimizer 상태를 이어받는 재개는 아닙니다. 기존 시도는 덮어쓰지 않습니다. 종료는 출력된 메인 PID에 `kill -TERM PID`를 사용합니다. 학습 자식과 데이터 로더도 함께 종료됩니다.

## 비교 조건과 결과

기존 실행의 데이터·fold 분할·부모 가중치·학습 횟수·고정 결합 계수·후처리를 유지합니다. 새 복사본에서 B4 worker의 시간 기반 시드를 제거하는 옵션을 켜고 Albumentations RNG를 명시적으로 설정합니다. HRNet의 worker 내부 데이터셋 RNG와 Albumentations RNG도 학습 시드에서 결정합니다. 학습 레시피와 입력 경로는 각 `train_command.json`에 기록됩니다. GPU 커널 수준의 비트 단위 결정성까지 강제하지는 않습니다.

후보는 독립 단독 모델 점수가 아닌 **최종 Model349의 image mIoU**로 비교합니다. 이미지별 네 클래스 IoU의 평균을 먼저 구하고, 20개 이미지에 대해 평균합니다. 정답·예측 모두 없는 클래스는 0이며 global mIoU는 계산하지 않습니다.

Model336 후보는 처음에 기존 Model347과 결합하여 비교합니다. 상위 두 부모에서 새 Model347을 학습하고 부모·자식 쌍으로 평가합니다. 마지막에는 각 구성 요소의 상위 두 후보와 기존 가중치를 이용해 최대 두 번 순차 조합을 개선합니다. 새 결합 계수 탐색은 하지 않습니다. 기존 조합과 최고 단일 교체 후보보다 나쁜 조합을 선택하지 않습니다.

`outputs/runs/seed100_시간/`에 다음을 보존합니다.

- `implementation/`: 실행 시점 소스·설정 스냅샷.
- `plan.json`: 100개 고정 작업·시드·의존성.
- `jobs/`: 후보별 모든 가중치·학습 명령·예측 확률·image mIoU·비교 이미지.
- `completed/`, `status.json`, `events.jsonl`: 완료 작업, GPU 배치, 경과 시간·ETA·중단 상태.
- `logs/`: 작업별 tqdm 진행률과 전체 실행 로그.

최종 결과는 한국 날짜 기준 `results/model_results_YYYYMMDD_다음번호/`에 저장합니다. Markdown 보고서, 후보 순위 CSV, 최종 `valid_mask_comparison/` 20장, 후보별 보고서와 비교 이미지가 포함됩니다. 2×2 배치는 좌상 원본 / 우상 오류 / 좌하 예측 / 우하 정답입니다. 맞은 픽셀은 흰색, 틀린 픽셀은 정답 색이며 상단에 image mIoU와 100%−image mIoU를 표시합니다.

`selected_model/`에는 선택된 **23개 가중치와 추론 코드·설정**을 복사합니다. 기존 모델·소스·결과는 읽기만 하며, 새 결과와 학습 시도는 기존 경로를 덮어쓰지 않습니다. 평가에 사용한 20장으로 시드도 선택하므로 최종 점수는 독립 test 성능이 아닙니다.

`./run.sh check`는 원본 입력 해시, 실행 소스, GPU 번호, 20장 고정 경로 재조합 점수 **80.06879890006227%**를 CPU로 확인합니다. 사전 점검은 학습과 GPU 추론을 시작하지 않습니다.
